# HLSGoals Agent API

REST API for driving a team's goal board. Authenticate every request with a
personal API token:

    Authorization: Bearer hls_...

Tokens are created by a signed-in user under "API tokens" in the app header.
The agent acts AS that user: team membership and the lead/member permission
matrix apply exactly as they do in the UI, and every action is attributed to
that user.

Token scope: tokens can do everything goal-related (create, edit, progress
updates, artifacts, assignments, complete/reopen, archive, carry-over) subject
to the owner's role — but they can NOT manage teams, members, or departments,
and can not create or revoke tokens. Those stay browser-only (403).

All request/response bodies are JSON unless noted. Errors: { "error": string }
with status 401 (bad/missing auth), 403 (not permitted), 404, 409 (rule
violation, e.g. completing a goal without an artifact), 422 (validation).

## Identity
- GET /api/auth/me -> { id, name, email }  (use to verify the token)

## Teams
- GET /api/teams -> [{ id, name, departmentId, departmentName, role }]
  role is "lead" or "member" and controls what you may do in that team.
- GET /api/teams/:teamId -> team detail with roster (read-only for tokens;
  use it to map names to userIds for assignments)

## Goal board
- GET /api/teams/:teamId/goals -> { goals: [...], currentPeriods }
  Each goal: { id, title, description, timeframe, period, status,
  parentGoalId, assignees, updateCount, artifactCount, ... }.
  timeframe: "yearly" | "quarterly" | "monthly" | "weekly".
  status: "active" | "completed" | "archived".
- GET /api/goals/:goalId -> full detail: description, assignees, updates
  (markdown), artifacts, parent/child links.
- POST /api/teams/:teamId/goals { title, description?, timeframe, parentGoalId? } (any member)
- PATCH /api/goals/:goalId { title?, description?, parentGoalId? } (lead only;
  parentGoalId: null unlinks; parent must be an active goal in the same team, no cycles)
- POST /api/goals/:goalId/rescope { timeframe }  (move between board columns)
- POST /api/goals/:goalId/carry-over  (bring an unfinished goal into the current period)
- POST /api/goals/:goalId/archive, /restore  (lead only)

## Progress updates
- POST /api/goals/:goalId/updates { text }  (markdown supported: headings,
  bold/italic, lists, links, code)

## Assignments
- POST /api/goals/:goalId/assignments { userId? }  (omit userId to assign yourself;
  assigning others is lead-only)
- DELETE /api/goals/:goalId/assignments/:userId

## Artifacts (proof of work)
- POST /api/goals/:goalId/artifacts  multipart/form-data with "file" and
  optional "note" (max 25 MB; common document/image/archive extensions)
- GET /api/artifacts/:artifactId/download
- DELETE /api/artifacts/:artifactId  (own artifact; others' is lead-only)

## Completing a goal
A goal can only be completed when it has at least one artifact attached
(accountability rule — completion requires proof). The flow:
1. POST an artifact (e.g. a PR summary, report, or export of the work)
2. POST /api/goals/:goalId/complete
3. To undo: POST /api/goals/:goalId/reopen

## Retrospective
- GET /api/teams/:teamId/retrospective?scope=team|department&granularity=quarter|month

## Recommended agent workflow
1. GET /api/auth/me to confirm identity, then GET /api/teams.
2. GET /api/teams/:teamId/goals to read the board.
3. Post markdown progress updates as work lands (link PRs/commits in the text).
4. Attach artifacts for finished work, then complete the goal.
5. Prefer small, frequent updates over rewriting goals; editing goal text is
   lead-only by design.
